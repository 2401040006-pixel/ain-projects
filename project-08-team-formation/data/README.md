# Data dictionary — Project 08 (Smart Team Formation Optimizer)

**All students in this folder are synthetic educational data.** There is no real class roster,
skill assessment, or attendance record behind these rows.

## Files

| File | Contents |
|---|---|
| `config.json` | Team-size bounds, roles, availability slot labels, skill field/range, and the four objective-term names (not their formulas or weights). |
| `scenarios.json` | Skill/schedule/role priority demos, the required weight-trade-off experiment, and the Hill-Climbing local-optimum fixture. |
| `students_seed42.csv` | 60 synthetic student rows generated with `scripts/generate_students.py --seed 42` (the default). |
| `SHA256SUMS` | Checksums of the three files above, so a regenerated `students_seed42.csv` can be verified byte-for-byte. |

## Columns in `students_seed42.csv`

| Field | Type | Notes |
|---|---|---|
| `student_id` | string | `S001`–`S060`. |
| `programming` | int | 1–10. |
| `mathematics` | int | 1–10. |
| `presentation` | int | 1–10. |
| `preferred_role` | string | One of `config.json["roles"]`: `Leader`, `Coder`, `Researcher`, `Presenter`. |
| `availability_vector` | string | Six `0`/`1` characters, one per `config.json["availability_slots"]` (`Mon`, `Tue`, `Wed`, `Thu`, `Fri`, `Sat`) in order. `1` = available that slot. Every student has at least one `1`. |

## The objective (`config.json["objective_formula"]`)

```text
J = w1 * skill_imbalance + w2 * schedule_conflict + w3 * role_imbalance + w4 * team_size_penalty
```

`config.json` names the four terms and documents what each should measure in words (see
`objective_terms[].description`). It does **not** give you a formula or fixed weights for any of
them — you design how `skill_imbalance`, `schedule_conflict`, `role_imbalance`, and
`team_size_penalty` are actually computed from the columns above, and you choose `w1..w4`
yourself. This is graded core work in `starter/student_core.py::objective`, not a data-loading
step. `data/scenarios.json` gives *example* weight profiles for demos, not required values.

## `scenarios.json`

Five scenarios:

1. `P08-SKILL-PRIORITY`, `P08-SCHEDULE-PRIORITY`, `P08-ROLE-PRIORITY` — example weight profiles
   that should visibly push the optimizer toward balancing that one dimension. Use these for the
   three priority demos.
2. `P08-WEIGHT-TRADEOFF` — the baseline (even) weights for the **required experiment**: change at
   least one weight from this baseline and report the trade-off.
3. `P08-HC-LOCAL-OPTIMUM` — a verified fixture starting assignment (`start_assignment`) for two
   4-student teams, `team_local_a` and `team_local_b`, built from real rows in
   `students_seed42.csv`. With `recommended_weights_to_reproduce` (`w1=1.0`, everything else `0`),
   every one of the 16 possible single-student swaps between these two teams either keeps the
   skill-imbalance score at 11 or makes it worse — a strict-improvement Hill Climber stops here.
   A 2-for-2 swap (documented in `escaping_two_for_two_swap`) drops the imbalance to 1. Use this
   fixture for the demo minimum "case Hill Climbing gets stuck in a local optimum", and to show
   Simulated Annealing (or a smarter neighborhood) escaping it.

## Regenerating the data

```bash
python3.11 scripts/generate_students.py --seed 42
```

This overwrites `data/students_seed42.csv` with a byte-identical copy of the committed file
(verify with `shasum -a 256 -c SHA256SUMS` from inside `data/`). A different, non-committed
sample is optional:

```bash
python3.11 scripts/generate_students.py --n 80 --seed 7
```

This writes `data/students_n80_seed7.csv` without touching the committed 60-row file.

## Verifying checksums

```bash
cd data
shasum -a 256 -c SHA256SUMS
```

## No pickled/trained artifacts

Everything here is CSV/JSON, generated by a plain, seeded `random.Random` stream in
`scripts/generate_students.py`. There is no pickle, joblib, or trained model in this folder.
